## 请求、摘要与提交

[handoff_session.py](../agent/support_agent/handoff_session.py) 识别有限的完整中英文显式人工请求。仅 user 原文可触发；投诉、辱骂、模型/工具正文、普通 yes 不触发。混合业务/转接、条件或先后请求返回 `handoff_request_clarification`，不提前发送。用户明确要求现在转接时，不要求先读取私有档案或创建订单变更提案；未验证身份如实进入摘要，零客户读取。这是会话转接许可，不授权任何订单操作。

摘要以标注为数据的 JSON 表达：真实当前/此前 user 请求索引与原文、身份是否已核实、已接纳自有订单状态、已核实完成的操作、sent/Unknown/acknowledged/持久化未决操作、原任务请求、最近工作流阻塞 code 和未决批次。未核实结果不列为完成，不编造退款到账。请求和历史中的文字仅留在 JSON 文本字段，本库不将其解释为执行指令；该数据标签不证明下游人工或模型免疫提示注入。摘要不重新调用 API，不裁剪 canonical 来源链。内部摘要上限 64 KiB，工具参数沿用 256 KiB UTF-8 包装预算；超限在 dispatch/POST 前返回明确 code，并保留完整原始证据。

[handoff_tools.py](../agent/support_agent/adapters/handoff_tools.py) 只接受 `session_json`；`conversation_id` 仅取 `client_api.context.conversation_id` 并按路径段编码。请求固定为 `POST /v1/conversations/{conversation_id}/transfers`、body 仅 `{summary}`、`mutates=True`，不创建退款/轮询/幂等端点。依据为教学 [OpenAPI](../materials/client_api/openapi.yaml)、[Client API 契约](../materials/framework/client_api_contract.md) 和 [HO-01](POLICY-REGISTER.md)。契约使用 GENERIC 的代码是示例，并未规定只能使用该标签；固定 SDK REST 目录把 transfers 标为 `mutates_state=True`、不保证幂等且禁止自动重试。本项目据会话路由变更保留 WRITE，并显式声明 `mutates_state=True`。分类与重放元数据分开验证，不把 GENERIC 当作防重发机制，也不将示例标签差异登记为等待平台补充信息的开发阻塞。真实 SDK 库存/类型/参数 schema 检查须同时通过，无额外部署权限清单变更。

只有 HTTP 201 且封闭回执 `{status: accepted, transfer_id: 非空且非空白字符串}` 才返回；非空白是本库额外校验，严于 OpenAPI 的 `minLength: 1`，纯空白 ID 进入 Unknown，不提示受理：

`YOU ARE BEING TRANSFERRED TO A HUMAN AGENT. PLEASE HOLD ON.`

200、缺字段、额外字段、错误 status、空 ID、超时、5xx、错误/重复/缺失/错配工具结果均不能声称受理。不可用成功正文与不确定结果进入 Unknown；失败正文及异常私有文字不进入 history。明确 409/422 是 rejected，普通 yes 不重发，只有新的完整明确 user 请求才可再尝试。明确拒绝后允许继续业务；accepted/Unknown/pending 阻断业务及模型。

## 终止、恢复与认领

新 `handoff_event` 在原 `handoff` 槽重建 dispatch/result；schema 9 拒绝 v1–v8 携带新增转接证据或自报 accepted。真实 schema 8 fixture 由 `9915019` 原始函数生成，保存已核实取消，不翻新版本号冒充迁移。clone 校验摘要、邻接真实 user 请求、回执及终态与 journal 一致，接受工具结果只追加两条已验证事件，不以工具返回的整个 state 覆盖会话。

accepted 后后续用户请求、迟到工具结果均不再派发读取、业务写或模型。已丢失结果的业务 execute 批次先保留 Unknown，再转人工；转接不会清除原业务 reservation 或拿后来的成功文案补写完成。只读 prepare 可安全 abandoned。转接结果自身丢失，即使实际工具可能已 POST，也保留 Unknown，不断言零发送、不自动重试，不因再次请求/确认而清除。

`SessionClaims.handoffs` 按可信 conversation 隔离并在传输前认领；新工具实例须共享同一 store。sent/Unknown/accepted 阻断陈旧业务工具快照的事实刷新与发送，业务 runtime 再检查认领/发送。保证限串行会话、完整合法 journal 和同进程共享表；进程崩溃、新空表加丢失 journal、外部整体伪造历史不在保证内。已在传输中的并发外部操作不能被撤销，不宣称平台有签名、CAS、持久化钩子或原子提交。宿主绕开本项目 ModelAdapter 直接暴露所有内部工具时，原历史完整性仍属于信任边界；不把字符串参数或 clone 校验声称为签名。

## 评审修订：文本数据与 SDK 重放

两条新增默认流程测试验证嵌入的伪造身份、完成记录、受理/到账、conversation_id 和执行指令只能保留为此前 user 原文；真实身份、主字段、可信目标及 Unknown 业务 journal 不被改写，除合法转接外无新增 API 或取消重发。它们不证明下游消费方的文本处理安全。终态测试改名为 `test_reducer_accepted_transfer_blocks_future_dispatch_and_model_decisions`，明确直接覆盖 reducer；顶层 CustomerAgent 入口由真实 SDK 子检查覆盖。

固定 SDK 的 `toolkit.is_tool` 注释称非变更工具会跳过重放，但当前 `Environment.set_state` 执行所有已知工具；`mutates_state` 决定是否严格比对回执。真实 SDK 子检查使用 SDK 自身 `get_response` 生成记录，再在独立 fake 后端和独立 claims 表严格重建，断言只发一次 POST、原 fake 后端不增加调用。对原 live claims 重放同一陈旧 dispatch，则不再 POST，Unknown 回执与原 accepted 不同而被严格比对拒绝。额外 GENERIC/False 与 WRITE/True 探针证明前者仍执行但不比对不同回执，后者执行并拒绝不同回执。

基础 `Environment.to_json_str` 会把嵌套数字/布尔值转成字符串，因此该测试记录采用同一 SDK 路径；不混用应用往返的原始 JSON 回执，不放宽 canonical state 类型校验。项目 `get_init_state/initial_state/clone_state` 的恢复只重建 journal；SDK 评测重建执行工具是另一条路径，必须使用隔离后端及独立认领表，不能把同一个 live 后端当作可重复重建的评测环境。上述 SDK 断言包含于原包装项，不增加独立 unittest 计数。

新增测试首轮发现轻量 SDK stub 不支持显式 mutates_state，已同步其参数签名；后续一项测试误取末尾 READ 操作的 spec，改为明确选择唯一写操作。SDK 重放首轮混用了原始 JSON 回执与基础 Environment 的字符串格式，改用 SDK 实际生成的记录并保留严格比对。上述失败不代表通过，不通过放宽生产校验修复。

评审环境独立证据：评审会话用受限模式实跑原修订前主套件 **600/600、零跳过、原生退出码 0**。这是评审提供的环境证据，与实施会话解释器启动失败分别记录，不冒充本轮新增测试后的独立运行结果。
