# M7 自然语言入口与 SDK 边界重构

2026-10-08，按用户“全面检查后重构 Agent”的要求实施。重构前问题见 [历史审计](M7-ARCHITECTURE-AUDIT.md)。此前默认入口未启用模型，身份和业务输入依赖有限语法；主要对话测试又绕过了 SDK 的真实结果序列化。这两点是实际设计与测试缺口，不能用此前本地合成通过数否认。

## 职责分界

| 交给模型理解 | 确定性代码负责 |
|---|---|
| 从普通语言提取姓名、邮箱、邮编，跨轮补齐信息 | 调用身份查询、独立比对后台记录，建立核验来源；客户 ID 或模型字段不能代替核验 |
| 理解查询、退换、修改、取消、地址、支付和转人工意图 | 工具白名单、参数类型、订单归属、状态资格、同单互斥和不支持的操作 |
| 从真实订单／目录解析商品描述、保留条件、否定、偏好、备选和预算 | 商品与规格存在、条件可表达、候选筛选、次数与顺序、不可静默降低约束 |
| 理解改口、撤回、条件性同意和当前版本的确认 | 完整复述、真实后一次 user、版本与 scope、事实指纹、执行前刷新、旧确认失效 |
| 理解跨单金额汇总、选中商品估计和退换比较 | 原有金额算法、舍入口径、类别分栏、可见交易与未知到账；分析不创建提案或许可 |
| 组织澄清和一般对话回复 | 写入结果和完整复述由已接纳事实生成；认领、只发一次、回执与自有读回、Unknown 不清除或重发 |

模型输出的是候选意图，不是端点写载荷或权限。生产 `create_agent()` 默认从平台 `get_agent_context().model_gateway` 建立语言组件，使用运行时模型允许列表和声明的参数选择；不用本机密钥，也不在包内配置提供商凭证。没有可用模型时受控拒绝，不回退到正则推断身份或业务同意。

## 实际运行链

原始 user → 平台模型解释 → 闭合候选结构与真实 user 引用校验 → 身份核验／授权读取 → 模型结合已接纳数据补齐请求 → 原有业务计划器 → 完整复述 → 新 user 的语义确认 → 版本与事实检查 → 内部写工具刷新／认领／发送 → 回执和自有读回。

姓名、商品和同意无需匹配固定句式。原始 `content` 不改写成内部 JSON 命令，也不构造假的 user。另存 `interpretation`，绑定原文哈希、真实 user 索引和逐字引用；schema 升为 13，旧快照迁移保留。模型失败时的 host 拒绝帧只表达“无语义许可”，避免字面 `yes` 在实时状态或历史恢复中落回旧确认解析器。

引用和哈希验证来源一致性，不能证明模型正确理解了语义，也不证明外部提供的整段历史真实。条件、描述和改口是否被模型正确表达仍需实际模型评测。确认候选必须引用完整最新回复，且只能指向当前版本；工具正文和 assistant 文本不能成为 user 同意。模型在工具结果阶段不能补造确认。

旧有限语法保留为低层规则端口及历史兼容路径；直接构造无语言组件的 `CustomerAgent()` 可以复验固定业务夹具。它不再是生产工厂的自然语言入口或模型失败后的后备理解器。M6 的固定 JSON／ID 输入和 522 条直接断言继续验证规则，不能扩大成新默认入口的语言能力证明。

## SDK 接口修复

`agent.py` 继续导出 `create_agent()`，返回对象继续实现 `get_init_state(message_history=None)` 和 `generate_next_message(message, state)`。实现允许放在随包辅助模块，不必把领域规则塞进入口。

`tools.py` 将导入的基类改为私有名，仅公开 `Tools` 供 SDK 发现。15 个注册工具和 READ／内部 WRITE 类型保持；`Tools.use_tool()` 在公开派发边界序列化一次 JSON 文本，内部领域方法仍返回类型化对象。这样真实 `Environment.get_response()` 不再将字典内数字／布尔值递归变成字符串，无需放宽身份、金额、回执或状态验证。

原 M6 固定批次改为通过真实 `Environment.get_response()` 交付结果，观察器仅解码实际返回文本，不能手工 `json.dumps(raw_dict)` 替代 SDK 传输。固定场景和业务预期未改。新增 M7 测试单独使用默认工厂、真实 SDK／ClientAPI／Environment 与脚本网关。

写工具派发后丢失结果、用户进入新轮次时，现在将未决执行明确记为 Unknown；晚到 bundle、恢复和后续请求不得清除它或产生重发。已接纳 Unknown 与丢失执行结果仍沿用各自已有边界。

## 来源与验证范围

保留 [M6.3 原基准](../tests/fixtures/m6_3_source_baseline.json)及 [M6.7 原变更清单](../tests/fixtures/m6_business_changes.json)不动，新增 [M7 逐文件变更链](../tests/fixtures/m7_semantic_changes.json)：16 个既有生产文件修改、3 个新增生产模块。每项保存明确理由及 before／after SHA-256，新模块 before 为 null。剩余 43 个前阶段项（含两份固定对话夹具）必须逐字节不变；当前多出文件、漏登记、错误哈希、理由为空或固定夹具变化均拒绝。清单和检查器进入执行来源摘要，不自动覆盖旧基准。

普通 READ 丢失结果后可发起新请求，但旧 READ 仍为 Unknown。模型投影只从已验证的非变更 journal 派生被放弃的 READ，将其表示为 host 的“没有接纳结果”观察；不补造工具成功、用户输入或后台事实，不改 canonical history。未决变更仍阻断模型，不适用这种恢复。

语义退货的去向改口回归还实际发现了新接线缺陷：首次请求索引 4 被新去向回复索引 18 替换，可能把后加礼品卡当成开启时已有。修法保留每单最早的实际请求来源边界，去向／清单更新不能重启资格时钟；探针核对 `gift_card_not_eligible_at_opening` 和零发送。预期与 M5 的资格规则未放宽。

读后 handoff 探针在修改前已通过零发送断言：既有转接事件门要求紧邻的真实 user，不能将它误报成新越权缺陷。本轮另在语义候选层显式拒绝读后 handoff，并要求 consent／handoff 都引用新 user 轮次的完整最新原文，避免把不合法候选继续交给下层。读后可解释或建议人工协助；真实新 user 的主管请求仍有正向对照。

离线测试中的模型返回由脚本网关事先指定，后台是合成数据。它们验证语言组件与业务守卫的集成、闭合候选拒绝和真实 SDK 传输，不是实际模型理解质量或正式课堂成绩。真实模型调用、费用、后台事务、到账及跨进程持久化未在本轮观察；保留 [M7 输入边界](M7-INPUT-BOUNDARIES.md)。本轮没有提交、推送或启动付费评测。
