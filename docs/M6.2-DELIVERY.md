## 范围

在现有默认 user→tool→提案→后次真实确认→写 journal→自有强读回上回归地址＋商品、默认＋订单地址、同单退换、多订单混合请求。组合请求需要澄清时不悄悄取其中一个执行；客户明确逐项后，地址先完成再商品锁单，各订单各自完整复述和确认。同单已申请退货不得换货，另一自有订单仍能建立独立新提案。没有新增自动拆分任意自然语言清单的调度器。

当前仍是一份可用提案集合：新展示遗漏的旧 scope 失效，不能用订单 B 的 yes 写 A。M6.2 测的是澄清和明确次序后的默认完整流程，以及同一集合的默认地址／订单地址两个独立操作，不宣称支持按订单长期并存的多个确认上下文。依赖完成只依据 succeeded journal 和自有强读回，不依据文案、发送过、地址相同或任务被省略。

多订单探针发现并修复了一处生产缺口：原 unfinished_other_tasks 会把**另一订单已接纳的 Unknown journal**当成全局阻断。现在六类生产器提供已验证 target（地址提供整组目标）；只有原计划之后确实已有该旧 scope 的发送 journal 且目标不同，才允许新记录进入完整复述。旧操作不被标记 task_completed、不改 status／receipt／read_ids、不释放其同单依赖，仍禁止重发。未尝试的其他任务、同记录依赖和未解决的全局批次继续阻断；调用方未提供 target 时保持原规则。专项对照覆盖 A Unknown→B 新换货／地址／支付／取消复述→后次 yes→B succeeded→A 仍 Unknown、客户默认地址的独立处理，以及丢失整个执行结果时 B／汇总均被阻断。

新增 [amount_summary](../agent/support_agent/amount_summary.py) 和默认只读有限入口：`Summarize order amounts: #TEST1, #TEST3`／`汇总订单金额：#TEST1，#TEST3`。模型、工具正文和历史 assistant 文字不能改变选择范围。所有 ID 必须属于已验证档案；跨客户 ID 在任何新读取前拒绝。档案不超过 32 单时，通过已有 list_customer_orders 重新核实身份并读取该客户订单，随后只汇总选定记录；超过该项目列表保护范围时，默认入口逐个派发已有 get_order，仅刷新选定订单。每个成功读取必须发生在本次真实 user 请求之后，旧快照不能冒充这次刷新；仍受每 user 请求 12 个 READ 预算约束。选定数量超过剩余预算时 summary_refresh_rule 返回 summary_read_budget_exceeded，派发前提示减少精确订单号或人工协助，不返回部分汇总。专项覆盖 33 单档案只读两单及选 13 单零读取；不新增 HTTP 端点、工具、schema 或模型调用，不把读取拆分变成业务写拆分。

内部 `summarize_amounts(state, order_ids)` 返回可解释 decision/code/details，默认回复渲染金额与证据类别，不把内部算法标签、journal 定位串或来源索引当成客户指令。该入口复制并校验 canonical state，没有修改 history／确认／后台的权限。已转接和任何未解决批次均不产生汇总；已接纳 Unknown journal 可以调查读取，但汇总标注 unknown，不能变成成功、到账或新写许可。

## 金额与来源

- 差价：每个订单保留既有 money.py 的完整清单、请求顺序 float 累加与最终 round(total,2)。跨单对各订单已形成的有符号差价按选定订单顺序再以该 helper 求沟通净额；两个订单仍分别发送，净额不进入后台载荷。
- 退货预计额：从每份提案／发送前的历史前缀取原成交价及所选重复次数，调用既有 return_refund_basis，精确原价合计与每单一次 half-up 显示值并存。跨单显示合计是**各单显示预计额的精确十进制和**，不重新对所有原价作一次全局 half-up。例：两单原价合计分别 0.010 和 0.005，各显示 0.01，分项显示合计 0.02，精确原价合计 0.015；两者标签不同。没有新增后台退款公式或通用差价算法。
- 取消：只保留该完整取消 spec 的原 charge 行，精确十进制相加、不舍入、不净额、不把历史 refund 当原款；失败申请不进入已提交范围。
- 可见退款：每个选定订单只采用最近接纳的有效订单快照，提案／申请回执／重读正文不再额外计一次。快照内相同方式／金额的两个 refund 行仍计两次，以 payment_index 保留次数；没有 transaction_id，不能按内容去重，也不声称跨快照发现每笔新增交易。读取失败、缺结果、被拒批次或最新列表未含目标时，旧快照不能补作新读取。
- 到账：公开 schema 没有处理器到账凭证，`arrival.amount=null/status=unknown`、`settlement_verified=false`。无可见 refund 行时可见退款合计也是 null，不把没有证据解释为零或预计额。return requested／exchange requested 只表示申请，不推断钱款执行。

已尝试的版本只从 journal 派生一次，不能再从 current proposal／receipt 增加一份。不同 scope 的预计额、取消原款、差价、可见交易和到账始终分栏，不把这些类别加成一个所谓“总退款”。不改变已有写前刷新、单次认领、Unknown 不重试、回执配对和 Counter 次数校验。

评审修订统一两层语义：精确来源字符串保持原精度和十进制表示，例如可见交易合计仍可为 `2.010`；顾客文案统一复用 money.display_exact_amount，至少两位、仅删除多余尾零，不舍入，`12.5 → 12.50`、`2.010 → 2.01`、`2.005 → 2.005`。取消逐笔／合计复述与汇总共用该函数；退货 exact_price_sum 仍明确显示来源值。没有相关差价／退货／取消证据时，类别金额均为 null、evidence_count 为 0；有证据且真实计算为零时保留零、计数大于 0，可见退款保留 row_count。源码捕获 ArithmeticError，故障注入证明 Decimal 算术异常返回 summary_amount_unavailable，不按已证实可达缺陷宣传。
