## 接口职责与状态口径

面向 Agent 的工具名称、参数、说明和返回结构，以及内部候选动作、任务、提案、确认和提示词，由本项目设计。平台规定工厂、轮次消息、Client API 和模型网关的集成方式；评测器调用我们的实现，不会替实现补齐模型调用或业务逻辑。

Python 网关的 `generate()` 签名、消息/工具对象、返回值及主要用量字段已经公开；TypeScript 对照也已取得。内部模型接口、候选与 fake 由项目设计，薄适配层按已知契约转换并验证真实 SDK。可选参数细节、异常类型和实际环境兼容仍待核实，检查接口不等于执行收费模型调用。JSON-only state 是本项目工程约束，平台契约将其定义为不透明状态对象。

### U6 补充：退款汇总的已知依据与待核实边界

退货预计额依据所选商品的原成交价，保留所选次数，不用当前目录价替代；取消则按实际支付历史及逐 charge 原路退款规则核对，不能与退货合计混为同一算法。[CASE-REQUIREMENTS](CASE-REQUIREMENTS.md) 的 A028-04、A046-05、A047-05 已要求报告实际选择范围的预计退款额，金额来源与业务范围并非未知。

目前公开 U6 只明确修改/换货差价和余额舍入，尚未明确退款合计在特殊精度输入下的累加、舍入时点及舍入规则。不得直接套用差价算法、逐项舍入或 Decimal 规则，也不以案例中的参考金额硬编码实现。该边界在 M3 金额规则、M5 退货实施前优先核对公开资料或向平台取证，取得依据后再增加退款合计函数和边界测试；不等待实际写入来证明操作前报价，不阻塞 M2 只读底座。

验收分别记录：操作前的预计额与来源；可读取的后台退款交易金额/方式；可证实的实际到账状态。当前教学 OpenAPI 的 OrderReturn 只有 item_ids 和 refund_payment_method_id，没有退款金额字段，申请回执不能独立证明合计或到账。后续仅在相关 payments 确实可见时核对交易，并在 M6 回归同单/跨单汇总、不重复累计回执及未知金额不默认零；未取得结算证据时不宣称到账。

状态：原成交金额与次数依据已明确；特殊精度的合计算法待取证；退款函数与业务测试未实现。本轮只登记，不扩大已完成范围。
