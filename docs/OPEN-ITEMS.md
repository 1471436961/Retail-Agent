### 当前证据文件的有效性

FOUNDATION-RUN 与 AT-TEST-TRACE 以同一个 run_id 绑定；新运行先将旧追踪标记 invalid，失败/跳过/输入变化不得留下当前 valid 追踪。各文件用临时同目录文件原子替换，两文件之间不假设事务；中断会留下 invalid 或不匹配的运行 ID，读取方必须同时验证两份文件及当前输入摘要。source_sha256 覆盖代码/测试/fixture；requirements_sha256 单独覆盖 CASE-REQUIREMENTS；specification_files 明列关键教学契约和规则/接口/退款证据的字节摘要，不覆盖任意文档、原始材料、权限文件或凭证。当前实现的完整校验函数为 scripts/foundation_trace.validate_evidence_pair。

## M4.1 的边界与后续承接

地址输入支持明确目标、字段标签、地址 JSON、五/六段完整地址及自有档案/订单复制；不声称识别任意口语。教学订单没有日期，不能从“最近订单”猜目标。初始条件或先后序列必须澄清；条件确认、撤回、改字段、事实变化不能支出旧同意。新展示仍沿用一份完整可用集合的规则，跨订单保留须显式纳入集合；没有独立多展示上下文。

address_pending 由原 history 的 dispatch/result/unknown/abandoned 重建，完整批次才接纳后继 state。只读 prepare 丢失/错误/拒绝或实际 user 插入下一轮时可安全 abandoned，重新准备或继续其他请求；迟到结果不能覆盖新 prefix。execute 丢失仍可能已写入，保留 unresolved reservation，不自动重发。两类 PUT 不具有跨记录原子性；第二项异常时保留已返回的第一项成功 journal，未返回的私有 journal 不能冒充可见结果。该限制不是新的外部等待项，不发明状态查询端点。

内部工具参数/结果预算已实现为 256 KiB/1 MiB 的序列化 UTF-8 字节，并在调度、工具解析和结果接纳边界检查。超限保留完整身份、同意和 journal；prepare 返回可恢复短诊断，execute 交付不全保持 Unknown。intake/prepare/execute 现在都有结构化 code 和逐记录诊断，write_authorized=false。WRITE 注册属于固定 SDK 支持的工具类型；模型仍只有八 READ，当前默认工厂不安装真实模型，也没有需要新增的 agent.json 工具权限清单。

地址 toolkit 默认拥有一份进程内 SessionClaims；同一个 live 后端重建 toolkit 可显式注入同一可信 store。不同重放后端使用独立 store。新空 store 配已丢失发送证据的旧 state 仍不保证跨进程去重，不新增 CAS/签名作为实现前置。执行只接受当前已确认的完整地址项；Unknown 订单不阻断另一自有订单，后台地址相同不冒充 Unknown 本次成功。
