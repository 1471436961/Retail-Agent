# Q2 长会话摘要与身份依据保留设计

2026-10-04 当前 M4.1 为 schema 6，在原身份/完整提案/任务/journal 上增加可恢复地址批次，见 [地址交付](M4.1-DELIVERY.md)。state 不裁剪，模型投影仍有界；以下 M3 段为历史阶段设计。原 user、独立验证、确认、已接纳事实及 Unknown 完整保留，不以助手摘要替代。

历史日期：2026-10-02。当时摘要/容量控制尚未实现；现已交付下述有界投影。适用于本项目 JSON state，不声称是平台字段或容量限制。

## 当前约束

[identity.py](../agent/support_agent/domain/identity.py) 的 supplied_by_user 只采信 user 原文；[state.py](../agent/support_agent/state.py) 校验 identity_evidence 与档案并按时间顺序恢复。[read_session.py](../agent/support_agent/read_session.py) 对工具候选、私有读取和结果复核同一范围。当前身份依据依赖完整历史，直接删除早期 user 文本会使 clone_state 拒绝；仅保留“身份已验证”的助手摘要不能修复这一点。

当前不得裁掉身份来源链，也不得通过取消 supplied_by_user 检查来上线摘要。本次模型摘要未删除 state 的任何消息或索引，因此没有裁剪迁移；未来 state 裁剪须与 schema、恢复及门控同步迁移。

## 保留与摘要的边界

| 信息 | 处理原则 | 恢复要求 |
|---|---|---|
| 用户独立验证输入 | 保留真正 user 原文、原始顺序及项目内部稳定消息引用；姓名/邮编分轮提供时保留全部所需消息 | 输入必须早于验证调用；不得从工具、助手回显或摘要重建原文 |
| 验证调用与匹配档案 | 保留验证方法、完整参数、call ID、已接纳档案、来源消息引用、原始验证轮次 | 仍须严格核对 customer_id、邮箱或姓名/邮编；verified 标志本身不能授权 |
| pending 与任务/确认证据 | 保留完整调用批次、ID、未决事项及未来提案/确认版本、原始用户授权来源 | 摘要不消除未决状态、不制造确认、不触发 API 重放 |
| operations 与已消费回执 | 保留状态及去重/写入结果依据；未来未知写结果不能压缩为“未执行” | 恢复后不重用 ID，不重复写；摘要不能宣称退款到账或完成操作 |
| 工具失败/错配正文 | 当前已替换为受控 read_result_status；ID/批次/必要 error 标志保留 | 模型与摘要只能收到安全状态，不收到原始错误或被拒绝的客户资料 |
| 普通解释与重复事实 | 可在独立的模型上下文投影中摘要，不直接修改受保护证据 | 模型摘要不是事实源、身份源或授权源；事实仍指向已接纳记录 |

受保护证据先保留在原 history 中，不从其他角色制造 user 消息。M3.2 已在 schema 2 中使用完整未裁剪 history 的索引绑定请求、完整复述与真实 user 确认；此为项目内部引用，不是假定 SDK 全局消息 ID，也不能直接适用于裁剪后历史。详情见 [M3.2 交付记录](M3.2-DELIVERY.md)。摘要第一阶段优先缩减模型投影，保持可恢复 state 的证据不变；若 state 容量要求进一步裁剪，必须先实施下一节迁移，保护 proposal/proposal_ack 元数据、报价依赖的已接纳目录来源、原 user 证据、读取批次与单调版本。助手摘要不能替代确认。

## schema 与容量迁移门槛

未来若将受保护证据抽成独立区，需升级状态版本并同时改造 clone_state、initial_state、范围门控和模型投影；不能只新增 identity_evidence 字段后放宽验证。迁移从现有真实 user 消息、已记录调用与接纳回执建立稳定引用，缺少来源时保持未验证并重新询问，不补造证据。校验独立区的用户来源、原始顺序、调用/回执关联、客户匹配和轮次边界，助手摘要永不参与授权判断。

裁剪后要记录历史起点/累计轮次及已消费 ID，保证 turn 单调、verified_at_turn 可追溯；当前按剩余消息重计 turn 的恢复方式不能原样用于裁剪历史。完整工具批次不能从中间截断；历史不完整时停止模型生成，而不是擅自补上成功结果。

当前模型投影内部预算为 48,000 JSON 字符，明确不是平台 token/state 上限；未来部署根据实测调整。如果身份、未决事项与去重证据已经占满预算，应保留安全门控并明确容量不足，不能删除证据后继续执行。

## Q2 实施时必须新增的验收

1. 邮箱与跨轮姓名/邮编两条路线：摘要前后 JSON 状态、历史恢复和私有范围一致；原始用户输入仍可追溯。
2. 删除或改为 assistant/tool 来源、使用更晚用户消息补早期验证、伪造独立证据引用：拒绝身份授权。
3. 有 pending、多调用、未来确认及未知写结果时，保留批次和去重依据；恢复零 API 调用，turn 单调，原 state 不变。
4. 旧状态迁移、缺失来源、超容量和异常工具正文分别测边界；SDK/fake 网关捕获模型载荷，证明未收到被拒绝正文。

2026-10-02 当时只落实恢复边界；2026-10-04 已实现有界模型投影并在真实 SDK 包装检查中实际验收。没有新增独立授权证据区。

## 2026-10-03 M3.2 审计补记

clone_state 每次重建提案台账，每个展示位置又恢复之前的只读历史；H 条历史、V 个版本存在约 H×V 的重复前缀处理，底层恢复还有自身成本，不能笼统称为随历史线性增长。版本随历史增加时可能接近二次增长。Q2 须测量 clone、恢复、确认检查及模型投影在历史/版本增长下的延迟和容量；当前没有性能上限验收或增量缓存优化。可设计可核验的增量证据缓存，但不能信任助手摘要、跳过来源复核或弱化台账比较来降低成本。

平台异常隔离包装保留可 JSON 化的损坏证据并终止所有后续处理，不作为新的身份/确认来源。非 JSON 证据无法持久化时明确记录 evidence_retained=false，不能静默生成正常空会话或把未知操作标为未执行；恢复须核实原始会话记录。

## 2026-10-03 M3.3 范围证据补记

M3.3 交付时 state schema 为 3，M3.2 的 schema 2 是历史基线。新的 proposal_set/proposal_set_ack 与逐完整操作 response 索引保留原复述和真实 user 范围回复；reuse_version 引用旧确认版本，恢复重新验证同意来源及相同语义/事实，不能只保留“第1项已确认”的助手摘要。迁移必须同时保留组内顺序、原展示、撤回/条件/改口、确认索引、读取来源及旧版本保留链；旧 schema 不接受夹带新范围元数据。详见 [M3.3 交付记录](M3.3-DELIVERY.md)。

## 2026-10-03 M3.4 任务来源补记

M3.4 交付时 schema 4 的 task_plan 元数据保存请求 action/target 列表及此前真实 user 索引；tasks 从对应计划原文和此前身份/自有订单引用重建，确定性任务 ID、依赖和冲突随展示索引产生。Q2 须同时迁移原计划、组内顺序、索引、身份来源、提案与确认保留链；不能只保留“任务1已完成”的助手摘要或当前任务图来替代来源。旧 schema 1/2/3 只接受空 tasks 且无新 task_plan 的形状。

## 2026-10-03 M3.5 写入证据与可信提交边界

当前 schema 5 沿用 operations，并在原 history 保存 write_event：完整发送 specification / 当前版本 / 刷新 IDs，结果分类及已规范化回执，后续自有强读回 IDs，checkpoint_uncertain / persistence_unresolved。旧 schema 1–4 不接受新元数据或 mutates=true；固定 a9d79a7 原函数生成的 schema 4 fixture 不创造发送或同意。恢复逐事件重放并严格比较，不执行历史 API。

sent 不证明 HTTP 已实际发生；恢复后与 Unknown、acknowledged 一样阻断重发。整体伪造的内部一致 history 是信任边界。当前 WriteRuntime 默认提交/业务评估及 claim/persistence/send 尚无生产实现，不能凭 JSON confirmed/delivery_verified 打开。项目应按正式课堂消息/状态及工具协议接入，验收范围内的单次发送、来源校验和恢复；不等待平台阅读/签名/CAS 才能开发。跨 worker/崩溃重启的持久化保证未证明，另列更强部署范围，不把后台重读或摘要哈希冒充它。

Q2 同时保护上述发送、结果、强读回、未决 checkpoint、任务计划、原 user 同意及 reuse_version 链。不能删掉 Unknown 的发送事件后把旧快照当新请求，也不能把仅回执或相同地址摘要成完成。只有有效发送/回执/读回且持久化无未决标志的结果可释放对应计划依赖；新计划不能借旧计划结果完成。schema 5 的额外 journal 重放也增加成本，尚无性能上限或增量优化验收，不能省略来源验证优化。

模型仅投影受控操作结果状态，不传 write_event 的内部参数、索引、读取引用；完整证据留在 state。默认路由不创建业务任务或写入，内部端口与 fake 验收见 [M3.5 交付记录](M3.5-DELIVERY.md)。此前各阶段“尚无结果 reducer”的描述是历史范围，M3.5 已加入通用离线机制，实际课堂发送/持久化端口仍未提供。

计划替换不记录已执行或成功，省略任务不是完成证据。M3.4 原批尚无结果 reducer；随后 M3.5 已补通用 journal 与依赖释放，tasks 仍不保存自报完成状态，真实业务端口未接入。任务恢复会追加前缀校验，未验收性能上限或摘要，不能通过取消来源比较优化。详见 [M3.4 交付记录](M3.4-DELIVERY.md)。

M3.4 评审补记：图无跨记录边不等于跨展示确认独立。当前只有一份可用提案集合，新集合遗漏的旧操作会失效；重新纳入且语义/事实未变的已确认操作由 reuse_version 串回原 user 证据。未来若采用按订单独立上下文，须一起迁移当前范围选择、版本、回复邻接和来源恢复，不能通过保留脱离来源的确认标志实现。当前 SDK 内部计划入口和候选诊断没有已交付业务流程调用者。

一个展示可包含多个完整操作，回放成本还随操作总数和保留链增加；此前 H×V 只是重复前缀量级说明，未计每组 scope 和底层成本。本轮没有性能上限验收或摘要实现。发送/状态一致提交约定扩展到完整操作集合，未获得平台送达、签名或消息完整性证据；不能以业务事实重读代替它们。


## 2026-10-04 已交付的有界模型投影

model_context.project_messages 先完整验证 state/history，再投影到 SDK 类型。短历史沿用完整消息；长历史生成带 authorization=none 的派生 SystemMessage，保留身份原 user 来源的说明、当前提案及未决写状态和近期完整消息组。摘要不是 UserMessage，不从中恢复独立身份或确认。工具调用与关联结果按整组保留；当前请求或受保护投影无法纳入预算时返回 InvalidAction，模型零尝试。原 state 不变，完整克隆/历史恢复依然验证全部来源。

实际 SDK 检查覆盖长历史、派生摘要不制造身份、超大当前请求和 pending 阻断；最新实际运行报告见收尾记录。投影节省模型载荷，不等于消除了 H×V 回放成本或解决无界 state；归档/裁剪/缓存是后续项目优化，不以缺平台数值作为外部阻塞。

## 2026-10-04 M4.1 地址批次与复述

schema 6 保留原身份、提案、任务、READ 和 write_event 结构；address_pending 只能由 address_dispatch/address_result/address_unknown/address_abandoned 原历史重建。仅只读 prepare 可 abandoned；execute 未决不能借该事件清除。address_assessment 保存结构化诊断，必须匹配最终文本且 write_authorized=false，不参与同意或权限判断。旧 schema 1–5 不能携带这些新标记或 presentation_note；schema 5 fixture 使用 622091c 原函数生成，迁移不创造 user 同意或发送。

内部地址工具收到完整 snapshot，canonical history 仅保存紧凑 dispatch，不递归保存含全部历史的工具参数。可信 toolkit 返回 reply/state/assessment 必须严格延伸该 prefix，无新增 user，身份来源相同，最终文本和诊断相同；prepare 无写事件，execute 新写只能匹配原已确认地址项。prepare 批次拒绝或实际 user 插入新轮次时记录 abandoned，不接纳其正文；可重新准备或继续其他请求，迟到结果不修改新 prefix。execute 批次拒绝仍记录 unknown reservation，不自动重发；第二项抛异常时保留此前已返回的第一项 journal，并将整个 dispatch 保持未决。恢复/克隆复核同一证据；尚未解决的 pending/execute Unknown 阻断模型投影，已 abandoned 的 prepare 不再阻断。

参数包按紧凑 JSON 的 UTF-8 字节限制为 256 KiB，结果为 1 MiB，属于项目内部工具预算，不是 REST 或模型预算。调度和工具解析前都检查参数，接纳时检查实际结果文本字节。超限不裁剪身份/确认/Unknown 链；只读结果可回退为保留原证据的短诊断，写后结果无法完整交付则保留 Unknown，不能以交付失败推断零写入。

presentation_note 只可附在完整 proposal_set，恢复时严格对照“说明＋原完整复述”文本；它解释被排除的状态或事实变化，不制造确认。真正金额/字段/目标/facts 指纹及 user 邻接同意沿用 proposals.py。SDK 的普通文本历史仍不能重建这些内部元数据；完整 opaque state 或本库 canonical history 的合法恢复是当前范围，整体伪造可信宿主历史仍非本库可独立证明的真实性。

本次发布以 workflow_boundary 的地址专属控制实现同一批次验证，只有 address kind；支付 slot/元数据与默认生产器不在本次提交范围。
