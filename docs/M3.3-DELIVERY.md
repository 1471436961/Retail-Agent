只确认同一换货/商品修改清单里的部分商品，属于改变该完整操作。候选缩减、追加和支付改变不会就地修改已展示 specification；可信生产器须解析新的完整范围、差价及方式，再展示新版本。修改后锁单或已经申请退换仍由原状态规则阻断，不能通过拆成多个 scope 绕过一次提交。公开案例 A005/A006/A021/A024 的改口/追加/撤回原则用于设计回归；没有将整个案例的真实业务执行计为已通过，也不按案例 ID 提前选分支。

条件以原 user 文本索引保留，不执行字符串表达式、不接受工具或模型声称 condition=true。明确编号的条件子句仅阻断相应操作；无法确定范围或执行先后条件时保守阻断整组。未来业务流程核实条件并决定方案后，通过新完整提案和其后的真实 user 同意验收该方案；当前不提供金额比较、资格查询、偏好回退选择或业务调度器。测试的已解析新金额由合成可信生产器提供，不能证明报价计算或礼品卡足额。

同意保留依赖 `reuse_version`：新展示事件引用当前已确认的完整旧 scope，重放时重新核实该旧记录确有真实 user 同意，且完整 specification、相关事实和语义摘要相同。变化/撤回/未确认的旧 scope 不能被保留；旧版本退出可用范围，新记录保留原 confirmation 索引并通过旧事件串回原复述。摘要仅用于一致性比较，不证明对话真实性。相同金额 int/float 不改变语义或重新计算金额。紧接本次集合复述的回复明确以 only/只/仅排除其他操作时，即使这些操作已有保留确认，也清除其许可。早前排除的结果仍保存在台账并随历史重放，被排除、未确认的操作不能自动保留；不把旧 only 文本当作对未来所有新提案永久生效的过滤器。

集合 ACK 明确只列已确认编号，元数据绑定每项版本/摘要/原 user 索引；随后重复 yes 仅保留已经确认的范围，不能顺便授权未确认项。插入其他问题或没有新复述的后续局部 yes 不能确认旧范围；需要重新展示。通用确认诊断仍为 decision/code/message/rules/details，并增加 proposal_withdrawn（deny）、condition_unresolved、proposal_amended、scope_not_confirmed、response_unresolved（needs_information）。所有匹配结果都只表示同意匹配，不能替代业务规则与 M3.5 写前核实。
