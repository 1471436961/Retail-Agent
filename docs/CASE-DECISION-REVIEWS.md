# M0 高风险案例的逐项决策审查

核对日期：2026-10-02。来源：[134 项公开案例](E:/enterprise-ai-materials/retail_plus/test-cases-5147314e-f2da-4bac-924a-e2ad95e647e4-zh.md:1)。此表只写**可复用的行为断言**，不复制固定客户数据和标准答案。完整 ID 与来源位置见 [追踪索引](CASE-TRACE.md)，规则编号见[规则台账](POLICY-REGISTER.md)。本表是需求审查，不表示 Agent 已实现或案例已通过。 当前教学接口解释见 [平台契约核查](PLATFORM-CONTRACT-NOTES.md)。

| ID | 原子行为与顺序 | 规则/API 候选 | 本地必须验证的负例 |
|---:|---|---|---|
| 5 | 首次确认时范围缩成只换台灯；若后来再次询问且客户改为退水瓶，则重新建立提案并按最终选择处理 | CF-02、ST-03、RT-01；订单读与退货/换货端点 | 不执行最早的两项换货；不把过早 yes 当最终授权 |
| 19 | 同单退与换无法兼办时，先分别核算两种方案，再按客户“最省钱”的条件选择且确认 | ST-03、MO-01、CF-01；订单/商品读与一种最终写 | 不先提交退货再发现换货冲突；不凭主观猜哪个更省钱 |
| 21 | 确认时追加一件商品，核对用户给的是 product 还是具体 item，重算整单商品修改清单与礼品卡影响 | IT-01/02、CF-02/03；订单/产品/item 读与一次商品修改 | 不按原单项清单提交；不把产品 ID 直接当 item ID |
| 25 | 先查自有订单及物流事实，先明确说明指定退款目的地是否受支持；不接受替代目的地时不启动退货，按条件处理人工请求 | ID-02、RT-02、CF-01、HO-01；订单/档案读、必要时转接 | 不擅自退到其他方式；不因结果标签“无业务变更”忽略人工条件 |
| 33 | 部分取消不支持时保留原订单；仍按订单商品解释可退金额；将档案默认地址改为客户确认的订单地址 | BN-01、AD-01、MO-01；订单/档案读、默认地址 PUT | 不取消整单或部分商品；不遗漏金额说明；不改订单地址 |
| 71 | 客户同时要订单地址与商品修改；支付方式和清单在最后确认时变化后，重算并确认最新提案；先完成仍允许的地址更新，再提交锁单商品修改 | AD-01、IT-01/02、CF-02/03、ST-02；两类写分别核实 | 不使用早先礼品卡或台灯提案；不先锁单导致地址未改 |
| 72 | 与 71 同一依赖，但用户先提商品；最终顺序按操作依赖和确认内容安排，而非按句子顺序盲写 | 同 71 | 不因“先提商品”先提交一次性商品修改 |
| 84 | 用户把退货商品从较便宜的一件改成较贵的一件，并更改退款方式；旧提案作废后重算 | RT-01/02、CF-02；订单/档案读与一次退货 | 不退最初商品或将款退至最初方式 |
| 91 | 客户继续补充退货列表和电子阅读器换货条件；在同单退换限制下澄清可行组合与最终选择 | ST-03、RT-01、EX-01、CF-03；订单/产品/item 读 | 不在客户仍追加商品时提前开启退货；不假称同单冲突可全部办理 |
| 92 | 首次确认时尚有商品未加入退货清单；重建完整列表并重新确认 | RT-01、CF-02/03；订单读与一次退货 | 不只退最初两件，不能二次追加 |
| 98 | 不同订单上的换货和取消分开检查；付款/退款方式在确认时改变，需失效旧提案。跨产品可接受不等于政策自动允许 | EX-01、CA-01/02、CF-02、IT-01；订单/产品读与合法写 | 不将一单确认套给另一单；不因客户同意就跨产品非法替换 |
| 105 | 两件原始规格相同的商品有不同目标规格，保留两次替换和顺序，按 ID 匹配规则核验回执 | EX-01、U5；订单/产品/item 读与完整换货列表 | 不去重或擅自统一目标，同 ID 不同价格/属性不承诺精确实例选择 |
| 119 | 两件同类商品各有不同原规格和目标规格，保留数量与逐件差价 | IT-01/02；订单/产品/item 读与一次商品修改 | 不丢失其中一件或按单件计算总差价 |
| 120 | 首次换货提交后同单追加另一商品应拒绝，并准确解释已提交的变更 | ST-03、CF-02；订单读 | 不第二次调用换货端点，不承诺稍后补办 |
| 125 | 首次 pending 商品修改后进入锁单状态，同单后续灯泡修改应拒绝 | ST-02、IT-01；订单读 | 不再次调用 item-modifications，也不转换为其他订单写绕过 |
| 130 | 用户明确只愿与真人沟通，按可信 conversation_id 转接并输出案例要求的精确提示 | HO-01；conversation transfer | 不伪称转接已受理；成功后不继续业务 API |
| 131 | 可以说明已有支付方式的可用性与差价；不能通过客服工具新增支付方式 | PY-01、IT-02、BN-01；档案/订单读 | 不创建新卡或把用户输入的新方式 ID 直接送写端点 |
| 132 | 对改邮箱请求解释服务边界，保留档案不变 | BN-01、EM3；按身份要求必要时读档案 | 不声称已改、已安排改，也不调用不存在的写端点 |
| 133 | 两件相同商品中只去掉一件属于数量修改，解释整单取消与单件移除区别 | BN-01、QS4；订单读 | 不取消整单，也不通过商品替换偷偷减少数量 |

U5 当前修改逐次替换首个 ID 匹配项，差价也按 ID 取匹配项；常规相同旧 ID 分别换不同目标已有契约依据。105/119 均保留次数与请求顺序并核验回执；同 ID 不同成交价/属性无法精确指定，不用内部 occurrence 冒充后端 line ID。差价测试遵循 float 顺序累加后 round，不以逐行舍入或另一算法替代。统一状态见 [实施事项寄存器](OPEN-ITEMS.md)。EM3/QS4 是材料裁决代号，不是教学 API 操作；测试使用合成订单和变化数据，不把固定案例值写入运行代码。

本表保留 19 项高风险优先组的决策摘要；全体 134 个 ID 的逐项拆解、来源/规则/API 关联和 522 条验收场景已在 [CASE-REQUIREMENTS.md](CASE-REQUIREMENTS.md) 补齐。剩余工作是关联实际业务测试函数及运行结果，本表不替代全案例追踪。
