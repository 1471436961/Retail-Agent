## 改动

- `get_customer_context` 是只读组合工具：模型从普通语言提取邮箱或姓名／邮编，可一次获得已验证客户、支付方式和指定订单。指定订单先与客户订单列表对照，再读取详情；重复 ID 只读一次。没有写入或自动重试。
- 保留全部原始工具方法和签名；为模型选取 16 个动作，四个身份原语由上述组合入口承担。SDK 仍注册 20 个工具，公开 HTTP 操作仍为原有 14 个。这三个数字不是同一计数。
- 替换流程和目录工具说明明确要求在选择、报价之前使用 `rank_preferred`；原始目录查询用于理解字段和商品信息。排序优先级仍由模型根据客户说明生成，不添加固定的价格、ID 或回退层次。
- `finish_response(message)` 是无业务 API 的控制动作。模型在实际结果已返回、全部请求已处理后选择该动作；Agent 将它转换成一条正常 `AssistantMessage`，记录完成状态，并通过可选 `is_stop` 返回真。没有按用户文本里的“完成”等词或轮次计数推断结束。
- 结束动作若与真正的工具调用同时出现，会等待这些调用的结果，不提前发出完成声明。普通提问、进度回复和未决请求继续原生轮次交互。

工厂和轮次方法签名、`Tools` 入口、原查询方法、换货批量参数与 REST 映射保留。每次 Agent 轮次仍只调用一次注入的模型网关，没有内部模型重试或新增预算参数。结束动作保留模型响应的用量／成本信息；它不授权或执行任何业务写入。
