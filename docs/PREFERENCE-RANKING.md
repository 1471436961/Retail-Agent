# 只读偏好排序工具

实现提交：`f5e4102`。本页记录工具设计和本地验证；远程成绩以对应推送的实际评测报告为准。

本页 47 项结果是排序工具提交时的本地基线。后续工具组织与会话完成修复的当前结果见 [会话完成](AGENT-COMPLETION.md)；排序条件与优先级仍由模型传入。

新增模型工具 `rank_preferred(order_id, item_id, allowed_options, sort_by)`。模型理解客户语言、解释目录用词、区分必须满足的条件与可权衡的偏好，再传入排序规则；工具读取原订单与同产品目录，按给定规则过滤和排序，不修改订单。

工具参数：

- `allowed_options`：硬约束，指定每个变化选项可接受的值；这些值的排列不是优先级。未提及的选项保留原值，显式 `null` 表示客户对该选项无要求。
- `sort_by`：模型根据用户说明传入的有序规则，列表靠前的规则先比较。价格规则为 `{"field":"price","direction":"ascending"}` 或显式降序；选项规则如 `{"field":"option","option":"backlight","values":["RGB","none"]}`，未列入该规则的值并列在其后。
- `sort_by=[]` 表示没有排序偏好。工具不自动补价格、商品 ID 或“主偏好优先”的规则；同排序值的候选返回相同 `preference_rank`，目录中的展示位置不代表偏好。

例如同样接受 clicky／full size，并允许 RGB 或无背光：

| 用户意思 | 模型传入的排序规则 |
|---|---|
| 优先 RGB，实在没有才接受无背光 | 背光规则，值顺序为 RGB、none |
| 两种背光都可以，价格最重要 | 价格升序放第一；不额外添加背光偏好 |
| 不在意背光，也没说明其他优先级 | 背光约束为 null，sort_by 为空，满足硬约束的可用候选并列 |

只有模型基于用户说明明确传入的条件参与比较。条件矛盾或需要选择而偏好不清楚时，模型追问，不要求客户学习工具参数格式。工具不解析自然语言、不硬编码商品同义词，不以代码固定任何用户偏好层次。

同产品、库存和硬约束用于过滤；缺货的匹配项单列为 `unavailable_matches`。输出保留 `effective_constraints`、实际执行的 `ranking_criteria` 和逐候选 `sort_values`，便于检查模型是否正确解释了用户意图。没有匹配时返回实际目录词汇供模型进一步解释、查询或追问。原订单的匹配购买价格单列，不以当前目录价替代。排序不产生确认或写入许可；模型仍需复述完整清单、差价与支付方式，再接收客户确认。
