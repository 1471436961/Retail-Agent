## 对话和记录语义

| 请求/后续输入 | 当前行为 |
|---|---|
| 指定订单或默认地址＋完整字段 | 先读相关自有事实，逐字段完整复述，首次展示零 PUT |
| 修正 Suite/城市等一字段 | 从该自有记录或当前用户 draft 保留其他字段，整份重述；旧同意不能执行新字段 |
| 显式新完整地址缺字段 | 要求补缺少的字段，不从旧地址偷偷补齐；后续真实 user 字段可补 draft |
| 从自有默认地址/另一自有订单复制 | 读取可信来源，不强制用户重复已知地址；all_orders 显式排除来源订单，即使同时修正字段也不把来源变成目标 |
| “默认地址＋订单地址” | 分为独立完整操作，各自确认/PUT/回执/强读回；订单先提交、默认地址最后提交，避免同组 profile 事实失效 |
| 部分确认某一编号 | 只提交该完整地址操作；另一项未确认不能跟随写入 |
| 非 pending 订单＋默认地址 | 明说该订单不允许更改，独立默认地址仍可展示和确认；不能把一个成功说成两个成功 |
| 所有自有 pending 订单 | 先读完整自有范围，排除其他精确状态；超预算先要求缩小范围，不先写部分订单 |
| 默认地址恢复原值 | 从最早已接纳档案取原地址，重新完整复述/确认，只恢复默认地址，不撤销已成功订单更新 |
| “最近订单”/未指明档案还是订单 | 澄清 exact order ID/目标记录；schema 无时间戳，不推断最新或 ETA |
| 初始条件/执行先后、条件确认、撤回 | 不自动求值或转成无条件同意；初始条件须澄清并提供新明确请求，字段修正不能消除该条件 |
| 写前事实变化 | 不发送旧版本；重新读取并生成含原因的新完整复述，需新 user 确认 |
| Unknown 或成功正文/强读回不匹配 | 不声称完成，不重试；后台地址相同不能证明本次 Unknown 成功。另一自有订单仍可独立推进 |

字段严格为 address_line_1、可空 address_line_2、city、region、country、postal_code；五个必填值为非空字符串，邮编保留前导零。不推断姓名、备注、地址簿、地理纠错或默认国家。支持中英标签、address JSON、显式五/六段逗号地址和明确 #订单/订单号；范围有限，未声称识别全部自然语言。六段顺序为街道、Suite、城市、区域、国家、邮编；不含 Suite 时五段。不明确的表达请求澄清。地址值中的 Payment、Default 或 #标记不变成业务动作或订单选择器。

## 状态与信任边界

schema 6 保持原身份/提案/任务/write_event 结构；address_pending 由紧凑 address_dispatch/result/unknown/abandoned 历史标记重建。工具 snapshot 不递归写入 canonical history，避免每轮嵌套完整历史。工具结果必须为一份匹配原 dispatch 的 reply/state/assessment，完整延伸原 prefix，身份来源相同、没有新增 user、最终回复和诊断相同；prepare 不能产生业务写事件，execute 的新事件只能匹配原已确认完整地址项。参数中仍有完整业务证据，单字符串函数参数本身不防伪造；真实 history 来自可信宿主，不以该参数当签名。

缺失、重复、错配、错误或被拒绝的结果正文不进入 history。只读 prepare 不可能发送 PUT，失败后记录 abandoned，可明确 retry 重新读取/复述，或继续独立读取；retry 不等于同意。实际 user 插入下一轮也安全放弃 prepare。迟到的 abandoned 返回不追加历史、不改变新的 pending prefix，只增加通常的轮次计数；不能复活旧提案。已放弃 prepare 不再阻断模型投影。execute 失败则可能已发送，仍保留 unknown reservation，不据丢失结果声称零写入、不自动重发；yes、retry 或重新提供身份不能清除它。恢复/克隆不调用 API，也不恢复时补发工具。

两类 PUT 是分别提交的非事务操作。第一项成功、第二项被拒/Unknown 时分别回报，不能说两项都成功或都失败。execute 的 terminal 控制事件在逐项结果之后记录；第二项出现预期边界异常时保留已返回的第一项 journal，整个 dispatch 标记 Unknown，并停止后继。第二项可能从内部克隆 state 已发送但尚未返回，所以宿主 state 不一定看见它的写 journal；不以缺 journal 推断零写入，也不回滚或重发第一项。读取和 runtime 初始化的预期异常返回脱敏 code；其他工具级失败仍按模式做上述保守处理。

intake/prepare/execute 共用 decision/code/message/rules/details 诊断，保存在最终 assistant 的 address_assessment，并与返回 assessment 比较；添加元数据不插入额外历史消息，仍保持用户紧邻完整复述。缺字段、歧义目标、状态拒绝、地址相同、刷新失败和逐记录写结果可区分。每份诊断带 records 和 write_authorized=false；诊断不是提案、同意或权限证据。

内部预算：序列化参数包（含 session_json 的 JSON 转义）最多 **256 KiB UTF-8**，紧凑结果最多 **1 MiB UTF-8**。调度、工具解析前及结果接纳都有检查，接纳还检查实际工具文本字节。预算是本项目工程约束，与 REST 请求上限、模型 48,000 字符投影和部署包上限分别计算，不声称是课堂工具限制。参数超限不调度工具，不裁剪身份/确认/Unknown；只读结果超限可返回保留完整原证据的短诊断。写后结果不能完整交付时抛 delivery error，宿主保留 execute Unknown，不截断 journal、不声称确定失败。真实宿主若采用不同转义，实际字节检查仍可能拒绝其返回，不能据紧凑预算保证任意宿主传输都成功。

[schema 5 fixture](../tests/fixtures/m4_schema5_state.json) 在本轮 state 修改前用 622091c 的实际原函数生成；不把 v6 形状改版本号冒充旧状态。schema 1–5 不允许携带新控制/说明元数据。普通 SDK 文本历史缺内部 proposal/控制元数据时不能重建同意；当前可恢复范围为正式 opaque state 或本库完整 canonical history，不声称从纯文本恢复全部业务。

工具运行时默认拥有进程内 SessionClaims。同一 live 后端重建 toolkit 可显式注入同一可信 store；正常重放在新后端使用新 store。单次发送保证限串行会话、合法完整 journal 与同后端共享进程表；进程和 state/表一起丢失或回滚仍无分布式去重保证。history 的真实性由可信宿主承担，本库不验证送达或签名，不新增 CAS/阅读回执作为开发前置。

仍使用单一可用提案集合：新展示遗漏的旧项跨订单失效，显式重新纳入的未变化项可按原规则保留真实同意。不是按订单独立多展示上下文。已有非地址/混合任务计划不得被地址生产器静默覆盖；跨流程整体调度归后续 M4/M5。
