## 实现与调用边界

[candidate_selection.py](../agent/support_agent/domain/candidate_selection.py) 是确定性纯函数，无 I/O/时钟/随机，不改入参，结果自持 JSON。返回 decision/code/message/rules/details，所有结果明确 write_authorized=false；唯一候选也不是提案或确认。复用 catalog 的原订单实例解析和 Product/CatalogItem 校验，不凭空要求 CatalogItem.product_id；同名跨 product 候选不能替换，同一个 item_id 不作为自身替代。重复原 item 的事实相同才可解析单个单位，不去重清单或声称已完成全部实例修改。

[candidate_session.py](../agent/support_agent/candidate_session.py) 与 [application.py](../agent/support_agent/application.py) 的 assess_candidates(state, request_index) 提供已实现的内部应用入口。调用者只传最新真实 user 历史索引，不传事实、criteria、confirmed 或 condition=true。入口严格 clone/replay 原状态，核验独立身份和自有订单引用，并从已接纳完整批次提取订单与完整 get_product 事实；它本身不调用 API、不追加历史或台账。最新相关失败/缺回执覆盖旧读取；单个 get_item 不能证明候选枚举完整；完整目录重读替换成员而非永久合并旧变体，成员的后续 get_item 成功更新库存/价格/属性，失败要求完整重读。handoff 和 pending 批次阻断，损坏状态在应用边界安全隔离。

**默认 generate_next_message 尚未调用这个入口，当前没有已交付商品业务生产器调用者。** 本批完成内部结构化选择，不声称任意自然语言购物意图已接入。M5.2 将复用该筛选器及现有严格身份/提案/确认/写 journal，不能另起更弱的状态或验证路径；候选事实在提交前仍须刷新。

## 请求契约

内部应用入口读取真实 user 的 JSON 文本，形状恰好为以下 envelope；criteria 六个字段均必需。示例为合成商品，不是案例答案。

```json
{"candidate_selection":{"order_id":"#EXAMPLE","item_id":"original_camera","criteria":{
  "hard":[{"field":"waterproof","op":"eq","value":"yes"},{"field":"price","op":"lte","value":{"original":"price"}}],
  "change":["resolution","waterproof"],"relax":[],"preferences":[],"fallbacks":[],
  "ranking":[{"field":"resolution","direction":"max"},{"field":"price","direction":"min"}]
}}}
```

- hard：field 为原商品属性名或 price；op 为 eq/in/lt/lte/gt/gte。eq/in 的属性值精确匹配，数值比较使用明确单位；value 可引用 {original: field}，从原订单读取，不拿原变体的当前目录价替代原成交价。
- change / relax：显式可改变的属性或客户明确放弃保留的属性，不能重叠或包含未知属性。两者之外的原属性全部保留；不因预算不限、颜色偏好或没有候选而自动放弃尺寸/材质/防水等约束。
- preferences：有先后顺序的 {field, tiers}；每个 tier 内值无先后，多个 tier 间有先后。偏好在硬约束/库存/保留属性之后应用，没有偏好匹配时保留当前合格候选；偏好本身不会自动开放该属性改变。
- fallbacks：按用户顺序列出完整 {hard, change, relax} 替代分支。仅当前全部合格候选为零才试下一分支；可替换主分支条件，但每个分支仍保留其未明确改变/放弃的原属性。主分支并列、读取失败或比较未知不启用回退，即使回退分支本身完全可判定：未知不能证明客户设定的“主分支无合格候选”触发条件成立。
- ranking：按用户明确优先级排列 {field, direction}，direction 为 min/max；先优化前一目标，只在最优并列候选内优化下一目标。没有声明目标优先级时不按代码顺序、最低价或 item_id 猜选。

数值比较使用独立 Decimal 上下文，单位表不可变，不受调用方精度或指数范围影响。输入测量的十进制数量级限定在 -324 至 308，这是内部比较范围，不是业务拒绝或平台上限。类型明确的数值 hard 参数在 criteria 校验时超范围，返回 invalid_selection_criteria 并带 input_error；测量字符串或目录事实在比较时超范围/不可解析，返回 comparison_unavailable，不猜零/无限大。ranking 没有数值阈值参数，其测量缺口在候选排序时诊断。数值比较不按字符串排序：mL/L、g/kg、mm/cm/m/inch 用明确十进制单位换算，GB/TB 按十进制前缀；未列出的单位仅允许同单位比较，不猜 GiB/GHz/CPU 质量关系。CPU 等非数值层级必须在比较或排序条件中给出明确 order，例如 [i3,i5,i7,i9]；未包含的层级/不可解析或不兼容单位返回 comparison_unavailable。order 不得用于 eq/in。没有竞争候选时不因无必要的排序测量提出多余问题。此测量语义是项目内部选择规则，不覆盖 money.py 的后端差价算法。

## 筛选次序与可解释结果

按优先级排序以逐步保留最优组实现，不凭空给同分候选安排先后；不是对所有落选项建立完整名次。每个分支依次记录硬条件匹配数、其中库存可用数、保留原属性后的合格数以及仍影响选择的未知比较数。明确违反另一硬条件的候选不会因无关的未知测量阻塞；已排除或缺库存的记录不影响最终排名。完整 options 和价格始终来自同一条 catalog item，结果保留原订单价格、合格候选和最终候选，不拼接不同规格。

candidate_selected 表示唯一候选；candidate_choice_required 返回仍并列的完整选项并明确询问客户选择/属性优先级。no_eligible_candidates 要求澄清而不发明放宽或跨商品替代；comparison_unavailable 表示测量/层级不足，不能等同零库存。排序无法比较时另保留当前尚待比较的 finalists、selected=null、失败字段 comparison_field 和原因 comparison_reason；这组候选已通过偏好及先前优先级，尚未选定或获得许可。catalog_facts_required/product_catalog_required/product_read_required/order_read_required 是事实缺口；invalid_selection_criteria 等带 input_error，区分调用构造错误与业务信息缺口。
