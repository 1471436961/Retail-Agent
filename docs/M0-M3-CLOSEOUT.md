## 可证明的单次发送范围

默认 WriteRuntime 是禁用基类。SessionWriteRuntime 的 SessionClaims 属于可信宿主/工具实例，不从用户 state 反序列化；相同后端会话的运行时实例必须共享它。认领和发送检查在进程内锁保护，完整 sent 事件先于唯一 HTTP 调用，返回值必须明确成功，dispatch 标记先于传输。受支持的串行会话、完整合法恢复、共享表下的陈旧快照重入不重发。恢复本身零 HTTP。

一个新空表配合丢失 sent 的旧 state，不能证明该后端从未收到操作；任意 worker/进程崩溃、状态回滚或丢失的跨进程去重不在当前保证内。需要该部署形态时必须另行实现持久化协调并验收。这是保证范围，不要求课堂新增 CAS，不把内存表称为持久化服务。

正常 payment-only 取消可以推进；已有 refund 的取消记录在发送前受控核实，避免已知固定上游全历史循环再次退款。支付切换对历史不是唯一 payment 的记录返回 current_payment_basis_unsupported，不凭净额猜当前方式。pending 的非空履约商品记录仍按该记录审查，不推断发货时间，也不阻断全部正常 pending。以上都是已实现异常策略，不等待未来文档。
