## 重复商品和规格处理

重复 item_id 按次数表达数量。同一旧 ID 的相同成交记录可对应多个不同目标，按请求顺序保留各次旧价/新价，整份清单通过后才输出差价。没有在 API 请求中加入 quantity、occurrence 或 order_line_id。

同一 ID 的成交价、产品、规格或名称存在不同实例时返回 `instance_selection_unavailable`，不猜选中哪一件。若较早替换产生了较晚请求的源 ID，则保守返回 `sequential_match_ambiguous`，避免首个 ID 匹配错选新插入商品；当前没有承诺解决所有此类清单的精确实例匹配。CatalogItem 无 product_id，归属来自产品外层记录。

硬规格检查要求目标完整 options 等于“订单原 options + 本次明确属性修改”；未要求的属性保持原值。目标缺失、畸形目录、重复产品或变体 ID、库存不可用、跨产品和超量选择均不能产生可用报价。

## 审计修复与阶段边界

保留三种 decision：缺少选择、金额、请求属性或可信业务事实返回 needs_information；已知禁令（如 quantity 修改、拆分支付）返回 deny；畸形候选参数（错误 ID 类型、未公开选择器、多余键、不匹配的属性列表、非有限金额）返回 deny 且 details.input_error=true，供调用方修正请求构造。损坏的目录/支付等事实输入仍要求刷新可信数据，不作为客户政策拒绝。输入错误标志不授权自动重试业务写入。

结果构造器仅接受 None/dict 的 details，拒绝 falsy 非字典和非 JSON 值，仍深拷贝可变数据。支付方式按教学 schema 的各 source 精确字段集校验，与付款历史的闭合键集保持一致；移除未使用的取消原因常量。私有 _payments 返回原列表供内部只读筛选，公共结果统一 JSON 拷贝，不向调用方暴露该别名。

订单门控顺序为能力范围 → 订单标识事实 → 精确状态 → 操作记录类型/状态一致性 → 状态专属拒绝 → 状态允许动作。匹配的操作记录不会解锁状态：其对应的 cancelled/return requested/exchange requested 均继续拒绝。身份来源和归属由未来调用方复用 M2 门控，不能由此函数代替。
