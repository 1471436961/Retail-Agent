## 夹具派生范围与逐轮精确轨迹

夹具 schema 2 为每个场景固定 `conversation_id/customer_id/order_ids/product_ids`。worker 的 Client API context 使用该 conversation_id；验证器从这些字段编码派生允许路径，并核对起始客户的 order_ids 与订单 customer_id，不信任扩大到他人订单的声明。无固定客户／订单／产品路径写死在验证器中，目标和上下文只来自预先写入的夹具，不从实际输出补齐。

每轮 `reads` 固定读取方法、路径、正文、顺序及次数；身份验证另保留完整 HTTP 轨迹断言。prepare 按档案／订单读取，涉及替换筛选时加相关目录；execute 保留写前刷新和写后档案／订单读回。允许路径上的多读、少读、错误正文和重排均失败。业务调用仍逐轮比较精确端点／正文与累计次数，不因读侧修改放松提前／额外发送拒绝。

写后自有读回从**本次写入路径和夹具目标**派生，必须在该次发送之后，不能用订单 A 的 GET 为订单 B 作证。新增另一个自有订单正向对照，以及保持读取列表正确却把目标读放在写前、只在写后读取别单的反向对照；不同会话 ID 及含斜杠／中文的编码由夹具验证。首批不因此声称已实现 M6.2 多订单业务调度。

原先固定起始完整后台 SHA-256、最终完整后台等于起点加显式 patches 的纪律保留；目标错值、无关记录改变、连起点一起改写都失败。当前 user 之后的诊断、身份、journal 和 handoff 终态分别核对，不以成功回复代替后台或回执证据。退货／换货成功仍只证明申请核实，不证明结算、到账或后台事务。

## 执行来源及发布边界

[SDK worker](../tests/sdk_m6_checks.py)使用真实 CustomerAgent.generate_next_message、tau2 消息、ClientAPI/Tools 和合成 transport；实际注册表／类型仍核对八 READ＋七个内部 WRITE。没有直接注入 verified/confirmed、不绕过默认轮次。每轮第十二次工具调用可执行，第十三次在 dispatch 前由共享预算守卫拒绝；计数边界和非法批次均有专项对照。

批次 schema 2 的 `execution` 保存 `mode/runner/sdk_version/parent_run_id/source_sha256/runner_inputs`，SDK 版本来自真实安装元数据，runner 与验证模块哈希来自文件字节。父入口传入实际 run_id 和冻结源码摘要；正常发布要求 native_sdk 模式且与报告同父运行／源码。缺字段、错误 SDK／runner／文件摘要、oracle_control 模式和旧父运行／源码均拒绝。

纯 oracle 单测使用显式 oracle_control 模式；仅测试结构校验时传入允许控制数据的参数，**正常 publish_run 没有此开关**，不能把这种数据发布成原生证据。正常入口只采集本次 wrapper 的 BATCH_EVIDENCE；嵌套运行保存／恢复外层上下文和证据，不能复用外层观察。元数据是可检查的来源追溯与混配防护，**不是签名，也不能识别整体被人工伪造的 native_sdk 报告**。不再声称 build_trace 能从任意 JSON 独立证明真实执行。

FOUNDATION-RUN.dialogue_batch 保留每轮实际 user、HTTP 轨迹、工具／参数摘要、回复、当前诊断／身份和完整起始／最终后台、journal。AT-TEST-TRACE.local_dialogues 保留全量计划、M6.7 归属与来源元数据；完整 business_result 仍 not_executed，remote_result 仍 not_run。读方须验证同 run/source/spec；失败、跳过、缺观察或输入变化不发布 valid。source 摘要包含 runner、批次验证器、夹具及文档校验脚本；新增逐文件变更对照，不含未选文档和凭证。测试中的 .env/Enterprise-AI.json 是临时目录内的合成哨兵，未读取真实凭证。
