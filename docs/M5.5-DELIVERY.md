## 实现修复与生命周期

矩阵探针发现此前 `Cancel only item … from order …` 可被解析成整单提案；该探针没有发送写。本轮增加有限范围识别 `cancellation_whole_order_required`，首次请求和活动草稿都只采信真实 user，原因 JSON/自由原因不派生范围。路由不会让旧确认覆盖当前输入错误，工具执行还重新解析范围：故障注入此前可接受的旧 execute 快照，也须在私有刷新/认领/发送前阻断。客户新明确整单请求才进入原完整复述/后次确认路径。没有添加部分取消、减数量或独立退款端点。

成功、409/422 确定拒绝、完整列表改口和超时/不可用 2xx Unknown 都覆盖三商品端点。拒绝比较 code、订单/档案和原 journal，成功比较完整 body/次数/强读回；超时可已有后台效果，不能称零发送或自动重发。已接纳的 Unknown journal 允许调查性读取但阻断受影响记录新发送；丢失执行结果的 Unknown reservation 全会话阻断读取/业务/模型。明确转人工保留原未知写。共享 store 重建 toolkit 的专项先恢复后端原状态，排除状态门掩护，再要求 write_already_claimed 和仅一次 POST。仍不证明任意新空表/状态丢失后的跨进程去重。

部分同意不提交整个重复清单；减清单重新展示新版本。提交后追加/改方式与地址/支付/取消绕过锁单均不开放。退货预计额/原 charge 取消/公开 float 差价仍各用已说明口径，线上只有契约业务参数，没有金额、数量、条件或来源字段。退换申请核实不证明账务执行/到账/发货；固定上游独立排序导致换货配错的 Unknown 边界仍保留，见[M5.4](M5.4-DELIVERY.md)。
